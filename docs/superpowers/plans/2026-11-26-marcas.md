# Fase B — Módulo de marcas: plan ajustado

Estado: **código en `feature/marcas` (PR a `develop`, sin fusionar)**. Los datos (mapeo) esperan la aprobación de la dueña. Nada se publica en `release` hasta que se ejecute el script de esquema.

## 0. Decisiones tomadas sin consulta (la dueña pidió autonomía)

| Tema | Decisión | Por qué |
|---|---|---|
| Almacenamiento del logo | Misma cuenta de Blob, **contenedor nuevo `brand-logos`** con lectura pública de blobs, igual que `category-images` | El código ya exige un contenedor por tipo de imagen. La identidad administrada del App Service ya tiene acceso a la cuenta, así que no hay cuenta nueva, ni permisos, ni costo. Con identidad administrada el API no crea contenedores: hay que crearlo una vez en el portal (paso del checklist). |
| Ruta del API público | `GET /api/marcas` y `GET /api/marcas/{slug}` | Las URL que pidió la dueña. |
| SVG | Se acepta con validación | Se rechazan `<script>`, manejadores `on…=`, `javascript:`, `<foreignObject>`, referencias externas (`http…` en `href`) y `<!DOCTYPE`/`<!ENTITY`. Además solo se muestra con `<img>`, que nunca ejecuta scripts. |
| Tamaño del logo | Máximo 1 MB; PNG, SVG o WebP | Un logo pesa poco; 1 MB deja margen sin permitir fotos enormes. |
| Mover de marca | El API responde 409 con la lista de conflictos si algún producto ya tiene otra marca. La pantalla pide confirmar y reenvía con `moveFromOtherBrands: true`. | Nunca se mueve un producto sin confirmar, y nunca queda con dos marcas (es una sola columna). |
| Página `/marcas/{slug}` | Fuera de las pestañas del portal, como el calendario | Tiene encabezado propio (logo, nombre y descripción) y su propio h1. |
| Filtros de la página de marca | El API devuelve los productos completos paginados (`pageSize` hasta 500). La página pide todos y filtra (categoría, precio, orden) y pagina en el navegador, igual que el catálogo digital. | Reutiliza los mismos filtros del catálogo. |
| Carrusel de logos en el home | Fila desplazable con flechas (sin animación infinita), después de los favoritos | Accesible con teclado. Se pide al cargar y queda debajo del primer pantallazo, así no causa salto. |

## 1. Modelo y migración

- `Brand`: se agregan `Slug` (nvarchar 120, índice único filtrado `WHERE Slug IS NOT NULL`), `LogoUrl` (nvarchar 500), `Description` (nvarchar 300), `IsFeatured` (bit, default 0) y `SortOrder` (int, default 0).
- `Product.BrandId`: `int` → `int NULL`. La FK sigue en `Restrict`: no se puede borrar una marca con productos.
- Migración EF `ExpandBrands` y tres scripts en `backend/database/marcas/`:

| Archivo | Cuándo | Qué hace |
|---|---|---|
| `00-consulta-mapeo.sql` | Ya | Solo lectura. Devuelve los 5 resultados pedidos. |
| `01-esquema.sql` | **Antes** de publicar | Columnas nuevas (`NULL` o con `DEFAULT`), slug calculado para las marcas existentes, índice único y `BrandId` nullable. Idempotente. El código actual sigue funcionando. |
| `01-esquema-reversion.sql` | Solo si hay que volver atrás | Quita el índice y las columnas nuevas y vuelve `BrandId` a `NOT NULL` (solo si no hay productos sin marca). |
| `01-esquema-verificacion.sql` | Después del 01 | Comprueba columnas, índice, slugs únicos y nulabilidad. |
| `02-datos.sql` | **Después** de publicar | Une las marcas duplicadas, aplica las asignaciones aprobadas, pasa "Sin marca" a `NULL` y desactiva esa marca. Idempotente y en una transacción. |
| `02-datos-reversion.sql` | Solo si hay que volver atrás | Restaura desde la tabla de respaldo que crea el 02 (`dbo.BrandMigrationBackup`). |
| `02-datos-verificacion.sql` | Después del 02 | Conteo de productos por marca y ninguna marca "Sin marca" activa con productos. |

Orden exacto: **01 → publicar → 02**.

## 2. API

Admin (`StoreAdmin`, `api/brands`):
- `GET /api/brands?search=` → marcas con conteo de productos.
- `GET /api/brands/{id}`, `POST /api/brands`, `PUT /api/brands/{id}`.
- `DELETE /api/brands/{id}`: si tiene productos responde 409 (hay que desactivarla); si no, la borra junto con su logo del Blob.
- `PUT /api/brands/{id}/logo` (multipart) y `DELETE /api/brands/{id}/logo`. Reemplazar el logo borra el anterior.
- `GET /api/brands/{id}/products?search=&page=&pageSize=`.
- `POST /api/brands/{id}/products` `{ productIds, moveFromOtherBrands }` → `{ updatedCount }`, o 409 con `{ conflicts: [{ productId, reference, name, currentBrand }] }`.
- `POST /api/brands/products/remove` `{ productIds }` → `BrandId = NULL`.
- `GET /api/products?withoutBrand=true` alimenta el filtro "Sin marca".

Público:
- `GET /api/marcas` → marcas activas con al menos un producto completo, con conteo, logo y si es destacada, ordenadas por `SortOrder` y nombre.
- `GET /api/marcas/{slug}?page=&pageSize=` → marca y productos completos paginados. 404 si no existe o está inactiva.
- Producto completo = activo, con foto y con precio detal > 0 (la misma regla del sitemap).
- `ProductDetailDto` y `CatalogProductListItemDto` agregan `brandSlug` (`null` si no hay marca), para enlazar la ficha a su marca.

## 3. Soporte de `BrandId NULL`

| Dónde | Cambio |
|---|---|
| `ProductService` (crear y editar) | `BrandId` opcional; solo se valida si viene. |
| Alegra | Nunca crea ni cambia la marca. Los productos nuevos llegan con `BrandId NULL`. Se elimina `DefaultBrandName`. El README deja anotado que, si a futuro Alegra trae marca, solo llenaría la marca vacía. |
| Catálogo, ficha y tarjetas | `brandName` vacío; la tarjeta y la ficha no pintan la marca. |
| Filtro "Marca" del catálogo digital | Ignora los productos sin marca (no aparece una opción vacía). |
| JSON-LD `Product` (Angular y función de Static Web Apps) | Se omite `brand` (ya lo hacía `publicBrandName`, que también descarta "Sin marca"). |
| Búsqueda | Sin cambios: busca por nombre, referencia o marca cuando la hay. |
| Pedido por WhatsApp | La línea omite la marca si está vacía (ya lo hace). |
| Catálogo PDF | Son archivos subidos, no se generan desde la base: no aplica. |
| Exportaciones | No hay exportaciones en el código actual. |

## 4. Frontend

- **Admin › Marcas** (`/admin/brands`), con la misma estructura que categorías:
  - Panel de lista: búsqueda, miniatura del logo, conteo, orden, destacada e inactiva.
  - Panel de formulario: nombre, URL (slug autogenerado y editable), descripción, orden, activa, destacada y logo (subir, reemplazar o quitar).
  - Debajo, "Productos de la marca":
    - Tabla con búsqueda y paginación.
    - Filtro Todos / Sin marca / De esta marca.
    - Selección múltiple con "Agregar a la marca" (confirma si mueve productos de otra marca) y "Quitar de la marca".
- **Admin › Productos:**
  - Selector de marca opcional ("Sin marca") en la ficha.
  - Opción "Sin marca" en el filtro de marca del listado.
- **Público:**
  - `/marcas` y `/marcas/:slug`.
  - Carrusel de logos en el home.
  - La marca de la ficha enlaza a `/marcas/{slug}`.
- **HTML para Google:**
  - Reglas `/marcas` y `/marcas/*` → `/api/seo-page` en `staticwebapp.config.json`.
  - Nuevos tipos `brands` y `brand` en `seo-page.js`, con las mismas reglas de 200, 404 y 503.
- **Sitemap:** agrega `/marcas` y `/marcas/{slug}` de las marcas activas con productos completos.

## 5. Pruebas

- Unitarias: slug (generación, tildes, unicidad con sufijo), normalización del nombre, mover entre marcas (nunca dos marcas), reemplazo y borrado del logo, y validación de SVG.
- Integración (EF en memoria y host HTTP):
  - Admin: CRUD, asignar, mover con y sin confirmación, quitar, desactivar o borrar.
  - Público: solo marcas activas y productos completos, y 404.
  - Sitemap.
- Frontend: carrusel de logos (sin logo no aparece, enlaces, teclado), gestión de productos de la marca, página de marca (SEO y 404) y `seo-page` (función).

## 6. Riesgos

1. **Orden de los scripts:**
   - Si se publica antes del 01, el API falla al leer las columnas nuevas.
   - Si el 02 corre antes de publicar, el código anterior no soporta `BrandId NULL` y falla al leer productos sin marca.
   - Mitigación: el checklist del PR incluye una consulta de verificación entre cada paso.
2. **Contenedor `brand-logos`:** si no existe, subir un logo devuelve error (el resto del sitio sigue bien). Hay que crearlo antes de cargar logos.
3. **Ficha de producto de Alegra:** sin marca por defecto, los productos nuevos aparecen sin marca hasta que se les asigne una. Es lo pedido.
4. **Mapeo:** los combos y kits (por ejemplo "COMBO PEQ #1 DEAR BODY Y MAQUILLAJE") salen marcados "Revisar". La dueña decide uno por uno.
